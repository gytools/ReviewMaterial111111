# 学习资料网站：账号与个人报告

本项目把原宏观经济网页改为 Cloudflare Worker：网页和接口都先验证登录，再从 D1 读取当前账号允许查看的报告。学生数据不在公共 JavaScript 文件中。

**当前状态：代码已完成本地功能和权限测试，尚未部署到 Cloudflare，尚未创建真实账号。** 浏览器布局、线上 D1 运行和 Workers Free 的 CPU 限制需要部署后验收。

## 使用方式

| 身份 | 可查看内容 | 可操作内容 |
| --- | --- | --- |
| 管理员 | 考试范围、全班分析、全部个人报告 | 批量或单独创建学生账号、修改可查看报告、停用账号、重置密码、导出 |
| 学生 | 通用知识材料、自己绑定的个人报告 | 修改自己的密码、导出自己的报告 |
| 未登录访客 | 登录页 | 输入管理员分配的账号密码 |

无需给学生绑定邮箱。学生首次登录必须修改初始密码。忘记密码由管理员重置。停用、重置密码、改权限都会使该学生的旧登录失效。

本版保留 Banner、分区、卡片和图表；导出使用 A4 横版。批量账号名单在管理员浏览器中生成，初始密码只在该页内存中保存；创建后及时下载，再分别发送。

## 部署

按随附的《部署教程.md》操作。使用 Workers Free、D1 Free 和默认 workers.dev 网址，无需购买域名。本项目不会主动开通付费套餐。

仓库应包含 `src/`、`migrations/`、`scripts/`、`tests/`、`package.json`、`wrangler.jsonc`、`.gitignore` 和文档。

**不要把 `private/` 上传 GitHub。** 它包含学生报告；部署时直接导入 D1。`.gitignore` 只保护 Git 命令提交，不能阻止你在 GitHub 网页里手动上传。也不要把原来含全部学生数据的 HTML 发到公开仓库或作为公开静态文件部署。

## 开发与验证

安装 Node.js 22 或更新版本后，在本目录运行：

```sh
npm test
```

不需要安装任何依赖即可运行测试。测试用内存 SQLite 模拟 D1 prepared statements 与事务；它不能替代 Cloudflare 上的实际验收。公开代码包里没有私有数据，第六组测试会跳过；完整部署包包含数据时会逐一检查 7 份个人报告。

测试覆盖：未登录访问、初始化口令与一次性创建管理员、请求来源、首次改密、按账号过滤报告、伪造参数越权、停用与重置后的会话失效、会话过期、退出、登录限速、页面脚本语法及全部个人数据隔离。

## 维护说明

- `APP_SECRET` 用于密码预处理，必须稳定保管。随意更换会使现有密码无法验证，不能把更换它当成普通更新。
- 密码使用随机盐、服务器 HMAC 预处理和 PBKDF2-SHA256（100,000 次），不存储明文。会话令牌仅在 Cookie 中，数据库存摘要。
- 登录有效期 12 小时；Cookie 使用 Secure、HttpOnly、SameSite=Strict；所有响应禁止缓存。
- 初始化完成后删除线上 `SETUP_TOKEN`，并从本地 secrets.json 去掉这一项。数据库中的初始化锁也会阻止再次创建管理员。
- 账号管理当前支持一位学生绑定一份个人报告；同一份报告可分配给多个账号，例如学生和家长。
- 上传新报告前验证其 JSON 结构和 HTML 内容。本版本的数据导入仅供管理员离线操作，不接受学生提交报告 HTML。
- 修改源文件后重新部署即可。修改学生数据要导入 D1；网页上传无法代替数据库更新。
- 线上验收要检查登录和改密在 Free CPU 限额下正常运行。如果出现 CPU 超限，先排查和调整实现，不要直接升级付费或降低密码保护强度。
